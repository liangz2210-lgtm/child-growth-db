# Child Growth Database

> 把「孩子在长大」这件事，从**流水账**变成**可分析的矩阵**，并让每一个判断都能被数据推翻。

一个纯本地的个人成长数据库框架。Markdown + JSONL + Python，无依赖、无云服务、可 git 版本化。

**它不是育儿 App，是一套数据工程方法。** 适用于任何想认真记录某个人长期发展的人。

---

## 为什么需要它

普通成长记录有三个绕不过去的问题：

| 问题 | 表现 |
|---|---|
| **记了就忘** | 相册里三千张照片，想不起一岁半时睡多久 |
| **记了没用** | 记了身高体重，但不知道下一步该改什么 |
| **记了不准** | 自报屏幕时间普遍低于实际 30–50%；不同照护者带的时段没人记 |

根因只有一个：**让人在记录的同时做计算**。

人做不到，于是只能记最简单的，复杂的整个丢掉——最后得到一个只有睡眠数据的"多维"表。

这套框架的解法是：**人只记录一句话，机器算所有指标。**

---

## 三个核心设计

### 1. 多维矩阵，不是流水账

**13 个核心维度 + 7 个元能力**，多分辨率采样：

```
T0 每天  → 只采 2 个（睡眠、情绪）
T1 每周  → 语言、自理、互动、屏幕、安全…
T2 每月  → 13 个核心维全过一遍   ← 硬约束
T3 每季  → 轨迹、变化点、假设回验
```

所有维度都日采 → 矩阵 97% 空白且必然断档。
**日常可以稀疏，月度必须完整。**

### 2. 事件流，不是填空

| 你说 | 系统得到 |
|---|---|
| 「他问了我三个为什么」 | 语言维 + 提问力维 + 频次 + 可追溯的原话 |
| 「今晚十点才睡」 | 睡眠维 + 熄灯时刻 + 与历史对比 |

**为什么这条最重要**：让人做计算，一定断档。让人只记录，才能持续三年。

### 3. 假设驱动，不是被动记录

系统维护的不是"数据"，是**可证伪的假设**，每条有期限：

> 「若把午睡截到 2 小时内，一周内他出现困意信号的时间会提前。
> **若没发生，说明入睡时间由环境因素主导，换干预点。**」

被证伪的假设和证实的一样有价值——这是它和日记的分界线。

## 快速开始

```bash
git clone <this-repo>
cd child-growth-db

# 1. 看校验器能拦住哪些错误（14 个故意写坏的样例）
python3 scripts/validate.py --fixtures

# 2. 校验示例事件流
python3 scripts/validate.py

# 3. 派生 L2 聚合（日/周）
python3 scripts/derive.py

# 4. 生成检视视图与缺口报告
python3 scripts/view.py
cat derived/gaps.md
```

无第三方依赖，Python 3.9+ 即可。

## 数据流

```
① 日常对话里的一句话
        ↓ 抽取成结构化事件（带原话、观察者、置信度）
② events/YYYY-MM.jsonl         ← 只追加，永不修改（唯一真相）
        ↓ 代码校验：字段、值域、重复、矛盾
③ derived/events.csv
        ↓ 代码聚合
④ derived/daily.csv / weekly.csv   ← 随时可重算
        ↓ 机器解释
⑤ 判断与建议
```

**为什么要分这么细**：原始观察被永久保留，指标定义改了可以重算全部历史。
直接往表格里写数字，事后无法回溯「这个 9.5 小时是怎么来的」。

## 三条铁律

| 编号 | 规则 | 为什么 |
|---|---|---|
| **R-03** | **禁止插补** | 缺失就写缺失。前向填充、均值填充、趋势估计，全是编造 |
| **R-04** | **只允许自下而上聚合** | 指标→维→域 可以算；反过来由域推指标，必然是假的 |
| **R-05** | **每个数可回溯到原话** | 追不到的不是数据，是印象 |

完整规范见 [`MATRIX.md`](MATRIX.md)（20 条，含执行者标注：哪些是代码强制，哪些只靠自觉）。

## 关键设计决策

### LLM 与代码必须分工

| 谁 | 干什么 |
|---|---|
| **LLM** | 理解语言、抽取事件、归维度、解释、生成提问 |
| **代码** | 校验、聚合、**所有数字计算**、异常检测 |

**铁律：任何从别的数字算出来的数字，必须由代码算。**
LLM 的算术是概率性的，而且错了不报错。

### 每条规则都要标注执行者

`code`（脚本强制）/ `prompt`（靠自律）/ `human`（人决策）。

诚实结论：20 条规范里只有 5 条有真正的技术强制，其余靠自觉。
**下一步该做的不是加规则，是把 prompt 类下沉成 code。**

### 每月升级，但默认否决

每月做一次外部检索（发展科学 + 数据工程），然后问：**当前数据库有没有真实痛点？**

没有 → 输出「本月无升级提案」，收工。

有 → 提案必须回答：借鉴了谁（附来源）、解决哪个具体问题（附数据）、不升级会怎样、代价、能不能退回。

并且硬约束：**每年结构性变更最多 2 次。**

> 连续 3 个月无提案 = 系统稳定，这是好事，不是失败。
> 这条是防「为升级而升级」——一个总在变的系统，数据永远攒不起来。

## 这套东西不做什么

1. **不做医疗诊断**。发现异常 → 转医生，附就诊准备清单
2. **不产生任何标准化发育评分**。量表施测交给专业工具与儿保
3. **不替代专业评估**。WHO 的 GSED 自己都写明「不可用于个体筛查诊断」
4. **不追求把矩阵填满**。它追求的是「关键的格子不缺」
5. **不承诺有效**。它是观察工具，不是干预方案
